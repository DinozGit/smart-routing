## 🔍 2. Пробелы, найденные сверх ROADMAP

ROADMAP описывает 4 незакрытых пункта. Код-ревью выявило **ещё 4**, часть из
которых важнее заявленных.

### 2.1 🔴 Fallback не работает в streaming-режиме

`router.py:1732` — ветка `if is_stream:` уходит напрямую к primary-провайдеру.
Цепочка fallback (`router.py:1816–1912`) существует **только** для non-streaming.

Zed, Cline, Cursor и большинство современных IDE-клиентов работают в
streaming. Значит, cross-provider failover в реальной работе **не срабатывает
никогда** — а именно он и заявлен как цель Phase 3.

> Корректная семантика (предлагаю): переключение разрешено, пока
> **не отправлен ни один байт клиенту**. Если провайдер упал на 5xx/таймауте
> до первого чанка — уходим на следующий в цепочке. Если упал посреди стрима —
> честная ошибка в SSE, подмена модели сломала бы поток.

### 2.2 🔴 `capabilities.max_tokens` из конфига — мёртвая настройка

`config.yaml:95,110,122` задаёт лимит per-role (`1048576`, `262144`),
но proxy его **не читает** — `/roles` отдаёт его в UI, а при запросе он игнорируется.

Cap из `context_length` (`router.py:1674–1686`) срабатывает только если
**клиент сам прислал** `max_tokens` (`if context_limit > 0 and client_max:`).
Клиент без `max_tokens` → провайдер применяет свой дефолт (часто = весь
контекст) → расходы неконтролируемы.

Побочно: 60% от контекста в 1M токенов = 629k — это не бюджет, это потолок.

### 2.3 🟠 Fallback-цепочка не пересекает провайдеров

`routing.json:20–24` — все три `role_fallbacks` указывают на **тот же**
`routerai`, что и основные модели. Проверено по каталогу: `deepseek-v4.1-flash`,
`deepseek-v4-flash`, `qwen3.8-27b` — все есть в каталоге routerai.

То есть даже при срабатывании fallback мы остаёмся на том же провайдере.
Отказоустойчивость между провайдерами заявлена, но не сконфигурирована.
Нужен формат **списка** цепочки: `routerai::X → openrouter::Y → ollama::Z`.

### 2.4 🟡 Каталог без ограничения размера

`models_cache.json` ≈ 1 МБ на 3 провайдера — `description` моделей
сохраняется целиком (известный баг №1, `router.py:_build_v2_cache`).

### 2.5 🟡 Статистика не переживает перезапуск

`state.stats` — in-memory (известный баг №2). Сейчас это не критично:
324 ₽ за 124 запроса.

## 🧭 Рекомендация

**Порядок: A → B, C отложить.**

| Спринт | Содержание | Почему |
|---|---|---|
| **Спринт 4** | **Вариант 0** (Q1–Q4) + A5 + A6/A3 | Закрывает реальные дыры (fallback мёртв при streaming, `max_tokens` игнорируется) дёшево и безопасно. UI остатков Phase 5 — в догонку, фронтенд параллельно. |
| **Спринт 5** | **Вариант A** целиком (A1–A7, если A1 не сделан в спринте 4) + начало **B** (B1, B2, B4) | Отказоустойчивость доведена до конца, параллельно готовим деплой. |
| **Спринт 6** | **Вариант B** целиком (B3, B5, B6) | Только если подтверждён сценарий деплоя (вопрос №4). |
| **По триггерам** | **Вариант C** | C1/C2 — когда появится запрос на историю затрат по дням или жёсткие лимиты. |

**Обоснование:** A1 и A2 — единственные найденные пробелы, которые **ломают
заявленную функциональность** (failover и контроль расходов). Они дешёвые.
B имеет смысл только при сценарии деплоя. C — самый дорогой и отложен
триггерами по решению из предыдущего спринта.
