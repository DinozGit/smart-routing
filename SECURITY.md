# Security Policy

## Supported versions

| Version | Supported |
|---------|-----------|
| `main` | ✅ |

## Reporting a vulnerability

Если вы нашли уязвимость — **не открывайте публичный issue**.
Напишите в личку владельцу репозитория или заведите приватный
[security advisory](https://github.com/DinozGit/smart-routing/security/advisories/new).

Опишите:
- что делает уязвимость,
- как её воспроизвести,
- какой ущерб она наносит.

Ответ ожидается в течение 7 дней.

## Модель безопасности

SmartRouter — **локальный агент**. Он слушает `127.0.0.1` и рассчитан на
запуск на одной машине, рядом с вашими IDE.

### Что роутер делает

- принимает OpenAI-совместимые запросы и проксирует их к провайдеру;
- хранит ключи провайдеров в `.env` и **никогда** не отдаёт их клиенту —
  в поле «API Key» в IDE можно писать что угодно;
- показывает стоимость запросов в админке.

### Чего роутер НЕ делает

- **Не аутентифицирует** входящие запросы. Любой процесс, который может
  обратиться к `127.0.0.1:8765`, может тратить ваш ключ и менять конфигурацию.
- **Не включает CORS.** Браузерные страницы не смогут управлять роутером.
  Это осознанное решение: с `Access-Control-Allow-Origin: *` любой открытый
  вами сайт получил бы возможность вызывать `POST /v1/chat/completions`
  и `POST /config` от вашего имени.
- **Не шифрует** трафик между клиентом и роутером — это локальный HTTP.

## 🔑 Отзыв ключа

Если ключ утекал, был показан в логах или попал в чужой репозиторий —
**отзовите его у провайдера** и сразу отключите его в роутере:

```bash
# 1. Отозвать ключ: удаляется из .env И из окружения текущего процесса
curl -s -X DELETE http://127.0.0.1:8765/providers/openrouter/key

# 2. Выключить провайдера целиком (обратимо)
curl -s -X POST http://127.0.0.1:8765/providers \
     -H "Content-Type: application/json" \
     -d '{"name":"openrouter","enabled":false,"base_url":"https://openrouter.ai/api/v1/chat/completions","models_endpoint":"https://openrouter.ai/api/v1/models","api_key_env":"OPENROUTER_API_KEY","requires_api_key":true,"pricing_mode":"auto"}'
```

| Шаг | Что происходит |
|---|---|
| `DELETE /providers/{name}/key` | строка `KEY=` удаляется из `.env` **и** переменная вычищается из `os.environ` — действует **без перезапуска** роутера |
| `enabled: false` | роутер больше **не обращается** к провайдеру: нет синка каталога, его модели исчезают из `/v1/models`, он не участвует в fallback-цепочке |

> ⚠️ **Ручное удаление ключа из `.env` недостаточно.** `load_dotenv()` при
> старте вызывается без `override=True`, поэтому (а) экспортированная
> переменная окружения побеждает файл `.env`, и (б) уже загруженный ключ
> остаётся в памяти процесса до перезапуска. Пользуйтесь `Remove key`
> в админке или `DELETE /providers/{name}/key`.

### Если ключ был экспортирован в систему

Проверьте переменные окружения — роутер унаследует их от того, кто его
запустил (IDE, терминал, systemd-юнит):

```bash
echo $OPENROUTER_API_KEY     # Linux / macOS
echo %OPENROUTER_API_KEY%    # Windows
```

Если переменная есть — уберите её из профиля оболочки, из настроек IDE и
из окружения запуска, затем перезапустите роутер.

## 📦 Что попадает в репозиторий

| Файл | Содержит | В git? |
|---|---|---|
| `.env` | **реальные API-ключи** | ❌ в `.gitignore`, никогда не коммитится |
| `.env.example` | только плейсхолдеры (`sk-or-v1-your-key-here`) | ✅ |
| `config.yaml` | провайдеры, роли, курс валют — **без ключей** | ✅ |
| `routing.json` | роли → модели, промпты — **без ключей** | ✅ |
| `models_cache.json` | каталог моделей и цены — **без ключей** | ❌ генерируемый кеш |

> Ключи провайдеров хранятся **только** в `.env` и в переменных окружения
> процесса. В `config.yaml` ключей нет — там только **имя** переменной
> (`api_key_env`), по которой роутер их читает.

Если ключ всё же попал в историю git — этого достаточно, чтобы считать его
**скомпрометированным**: публичный репозиторий клонируется, а история
доступна всем. Отзовите ключ у провайдера — очистка истории его не отменяет.

## Рекомендации

- Не выставляйте порт `8765` наружу без аутентификации и TLS-терминации.
- Если нужен доступ из другой машины — используйте SSH-туннель:
  ```bash
  ssh -L 8765:127.0.0.1:8765 user@host
  ```
- Держите `.env` вне репозитория (файл уже в `.gitignore`).
- Для публичного развёртывания добавьте обратный прокси с TLS и авторизацией.
- **Выключайте провайдеры, которыми не пользуетесь** (`enabled: false`).
  Это ограничивает «blast radius»: даже при ошибке в маршрутизации или в
  конфигурации роутер физически не обратится к провайдеру, который вы
  отключили.
- Назначайте ролям только те модели, которые действительно нужны: роутер
  не выбирает провайдера неявно — голый `model_id` из клиента резолвится
  только в каталоге провайдера по умолчанию.

### Ответственность пользователя

Ключи провайдеров выдаются вам провайдером и хранятся у вас. Роутер лишь
использует их по вашему указанию.
